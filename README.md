# Сайт ФКНТ — Astro SSG (стартер)

Статичний сайт факультету: швидкий, безпечний, з новинами як контент-колекцією.
Дизайн — за брендбуком ФКНТ (сині/жовті токени, Mulish + Dela Gothic One).

## Запуск локально
```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # збірка в ./dist — готові статичні файли
```

## Що демонструє стартер
- **Сторінка = шаблон + дані + layout.** Дивись `src/pages/faculty/departments.astro`:
  8 кафедр НЕ написані руками — вони беруться з `src/data/departments.json`
  і проганяються через компонент `DepartmentCard.astro`.
- **Спільна оболонка в одному місці.** Шапка/меню/футер — у `src/layouts/Base.astro`.
  Правка меню тут застосовується на всіх сторінках (жодного дублювання, на відміну від старого сайту).
- **Новини без верстки.** Додав `.md` у `src/content/news/` → зʼявилась картка у стрічці
  `/news/` + окрема сторінка статті. Схема в `src/content/config.ts` не дасть опублікувати «криву» новину.

## Робочий процес «майже без ручної роботи, з телефона»

```
Опис завдання (телефон)                          Публікація (телефон)
   Claude Code mobile / @Claude у Slack  ─►  PR  ─►  Merge у GitHub-застосунку
        │                                             │
        ▼                                             ▼
  агент читає AGENTS.md,                        Cloudflare Pages
  робить зміни, відкриває PR                    автоперебілд + деплой
```

1. **Один раз (setup):** створити репозиторій, підключити Cloudflare Pages до гілки `main`
   (білд-команда `npm run build`, тека `dist`). Далі кожен push у `main` = автодеплой.
2. **Щодня (з телефона):**
   - Пишеш агенту звичайною мовою: *«Додай новину про перемогу на хакатоні 18.05, ось фото»*
     або *«Додай кафедру X із сайтом Y»*, або *«Зроби відступ у картці більшим»*.
   - Агент за `AGENTS.md` вносить зміни й відкриває **PR**.
   - Ти відкриваєш PR у GitHub-застосунку, дивишся diff, тапаєш **Merge**.
   - Cloudflare сам збирає й викладає оновлений сайт за десятки секунд.

### Що лишається за людиною (і це навмисно)
- Рішення про дизайн і структуру.
- **Перевірка офіційного контенту перед злиттям PR** (імена, дати, факти, тон).
- Разове налаштування репозиторію, домену й Cloudflare.

Автопублікація без рев'ю для офіційного сайту факультету свідомо **не** робиться.

## Наступні кроки (для агента чи розробника)
- `src/data/nav.json` + компонент `<Nav>` з повним мега-меню (замість спрощеного в Base).
- Сторінка статті `src/pages/news/[...slug].astro` + пагінація стрічки.
- RSS через `@astrojs/rss`, `sitemap` через `@astrojs/sitemap`.
- Редиректи зі старих кирилічних URL (`_redirects` для Cloudflare) — щоб зберегти SEO.
- Headless-адмінка (Sanity/Directus) або Google Docs-конвеєр — якщо редактори не хочуть навіть PR.
