# Панель контенту (Sveltia CMS) — налаштування

Автор заходить на `https://fcst.kai.edu.ua/admin/`, бачить форму «Нова новина»,
заповнює заголовок / дату / категорію / обкладинку / текст і тисне «Зберегти».
Далі — рев'ю й публікація. Жодного коду чи Git з боку автора.

## Файли
- `public/admin/index.html` — сторінка панелі (вантажить Sveltia з CDN).
- `public/admin/config.yml` — колекції та поля форми (поля = схема `src/content/config.ts`).

## Разове налаштування автентифікації
Sveltia — **Git-based**: щоб зробити коміт/PR, потрібен вхід через GitHub. Кроки:
1. Створити **GitHub OAuth App** (Settings → Developer settings → OAuth Apps).
2. Розгорнути безкоштовний **`sveltia-cms-auth`** Worker на Cloudflare (у вас уже є Cloudflare),
   вписати в нього Client ID / Secret з кроку 1.
3. У `config.yml` вказати `base_url` = адреса цього Worker.
4. Захистити гілку `main`: обов'язковий PR + рев'ю (Settings → Branch protection).
5. Дати авторам доступ до репозиторію за принципом мінімуму (лише цей репозиторій).

## Про Google-вхід — чесно
Git-based CMS автентифікує через **GitHub**, а не Google напряму: коміт має бути
прив'язаний до Git-особи. Тому є два реальні шляхи:

**A. Sveltia + GitHub (найлегша інфраструктура).**
Кожен автор має GitHub-акаунт в організації з доступом лише до цього репо.
Підходить, коли редакторів небагато. Щоб додати ще й корпоративний бар'єр —
поставте `/admin/` за **Cloudflare Access з Google SSO**: панель відкриється
лише для акаунтів `@kai.edu.ua`, а комітить усе одно GitHub-особа.

**B. Headless CMS + Google SSO (автори взагалі без GitHub).**
Якщо мета — щоб викладачі логінилися лише корпоративним Google і не мали GitHub,
потрібен headless CMS (Directus / Sanity) з власними користувачами й Google SSO;
службовий бот комітить від їхнього імені. Це окрема система для хостингу, але
дає найзручніший онбординг для нетехнічних авторів.

**Рекомендація:** почати з A (мінімум інфраструктури, вже показано в цьому стартері);
якщо авторів багато й вони нетехнічні — мігрувати на B, фронтенд лишається той самий.

## Примітка про сторінки
Колекція `pages` у конфігу редагує сторінку лише якщо її змодельовано як **контент**
(`src/content/pages/about.md`), а не як `.astro`-розмітку. Тобто текст, який мають
правити автори, виносимо в markdown/дані, а `.astro` лишається шаблоном.
Новий **макет** сторінки — це завдання для агента/розробника через PR, не для CMS.

## Безпека — коротко
- Секрети (OAuth Secret тощо) — лише в Cloudflare/GitHub Secrets, ніколи в репо.
- Токен ШІ-агента — вузький (fine-grained PAT): лише цей репо, лише PR, без push у `main`.
- 2FA для організації; розділення ролей: код ≠ контент.
- Прев'ю-деплої — за Cloudflare Access, щоб чернетки не були публічними.
