# Заливка новин: Google Docs → сайт

Автор пише новину звичайним Google Doc у спеціальній теці на Диску й нічого
більше не робить — ні Git, ні CMS, ні кнопок у документі. Автоматизація сама
знаходить нові документи, перетворює їх на новину сайту й публікує.

Працює **без claude.ai** і, за замовчуванням, **без жодного платного API** —
увесь конвеєр живе на Google Apps Script (безкоштовно) + GitHub REST API
(звичайний PAT). Ніяких MCP-конекторів, ніякого GitHub App, ніяких хмарних
routine, ніякої обов'язкової оплати.

```
Google Doc у теці fcst_news  →  Apps Script (погодинний тригер)
    →  Drive API: список докʼів у теці  →  automation/news-processed.json (нові?)
    →  експорт у Markdown  →  розбір шапки документа (без AI)
    →  коміт напряму в main (GitHub REST API)  →  Cloudflare перебілд  →  новина на сайті
```

## Що робить автор
Пише новину у звичайний Google Doc. **Перші рядки документа** — проста
текстова шапка, кожне поле на своєму рядку, без жирного чи інших стилів:

```
Заголовок: Команда ФКНТ перемогла на хакатоні
Дата: 2026-08-03
Категорія: Досягнення
Опис: Студенти посіли перше місце з проєктом виявлення кіберзагроз.
```

Далі — порожній рядок, і після нього звичайний текст новини (можна з
підзаголовками, списками — усе, що підтримує Google Docs).

Категорія — одне з: `Новини`, `Досягнення`, `Події`, `Вступ`, `Наука`.

Кладе документ у теку **fcst_news** на Google Диску
(`https://drive.google.com/drive/folders/1nP2R8SgJ5oqNH0SqJ7WoyDUICk_LcS0f`).
Усе. Протягом години новина сама з'явиться на сайті.

**Якщо шапку заповнено неповністю або з помилкою** — скрипт все одно
опублікує файл (щоб нічого не загубилось), але позначить його
`draft: true`: новина НЕ з'явиться в стрічці на сайті, доки хтось не
відкриє `.md`-файл у репозиторії, не перевірить/поправить поля та не
прибере `draft: true` вручну.

## Як це працює технічно (`automation/publish-news.gs`)
1. Погодинний тригер запускає `scanAndPublish()`.
2. Скрипт перелічує Google Docs у теці `fcst_news` через Drive API.
3. Звіряє `id` кожного документа з `automation/news-processed.json` у
   репозиторії (читає файл через GitHub Contents API) — пропускає вже
   опубліковані.
4. Для кожного нового документа: експортує Doc у Markdown (нативний експорт
   Docs), **розбирає перші рядки як шапку** (`Заголовок:`, `Дата:`,
   `Категорія:`, `Опис:`) — без жодного виклику зовнішньої моделі.
   Усе після шапки стає тілом новини як є.
   - Немає поля → підставляється безпечне значення (назва документа як
     заголовок, сьогоднішня дата, категорія «Новини», перші ~220 символів
     тексту як опис) і файл позначається `draft: true`.
   - Є всі чотири поля коректно — файл одразу `draft: false` і публічний.
5. Комітить `src/content/news/<дата>-<слаг>.md` **напряму в main** через
   GitHub REST API (Contents API, без гілки й без PR) — свідомий виняток із
   золотого правила AGENTS.md, узгоджений з власником сайту саме для цього
   конвеєра.
6. Оновлює `automation/news-processed.json` (`docId → slug`) окремим комітом.
7. Cloudflare Pages підхоплює пуш і перебілдовує сайт автоматично.

### Опційний AI-фолбек (вимкнений за замовчуванням)
Якщо колись захочете, щоб документи без жодної шапки теж нормалізувались
розумно (а не просто йшли в `draft: true` з витяжкою з тексту як опис) —
можна увімкнути виклик Anthropic API:
- Додати Script Property `USE_AI_FALLBACK` зі значенням `true`.
- Додати `ANTHROPIC_KEY` — ключ з console.anthropic.com (**не** обліковий
  запис claude.ai — окремий платний API-ключ).
Спрацьовує лише для документів, де в тексті взагалі немає жодного з полів
шапки. Якщо на ключі немає оплати/кредитів — виклик просто впаде з
помилкою, скрипт це зловить і сам відкотиться на розбір шапки без AI
(побачите в Executions лог «Claude API недоступний»). Нічого не ламається.

## Разове налаштування
1. Тека `fcst_news` на Диску `oleksandr.vdovychenko@kai.edu.ua` — вже створена.
2. [script.google.com](https://script.google.com) → New project → вставити
   вміст `automation/publish-news.gs` як `Code.gs`.
3. **Project Settings → Script properties** додати:
   - `GITHUB_TOKEN` — fine-grained PAT: лише цей репозиторій, право `contents:write`
   - `GITHUB_REPO` — `OleksandrVdovychenko/sites_fcst`
   - `BASE_BRANCH` — `main`
   - `DRIVE_FOLDER_ID` — `1nP2R8SgJ5oqNH0SqJ7WoyDUICk_LcS0f`
   - (опційно, лише для AI-фолбека) `USE_AI_FALLBACK` = `true`, `ANTHROPIC_KEY`
4. У маніфесті (**View → Show manifest file** → `appsscript.json`) додати:
   ```json
   "oauthScopes": [
     "https://www.googleapis.com/auth/drive.readonly",
     "https://www.googleapis.com/auth/script.external_request"
   ]
   ```
5. Запустити функцію **`installTrigger`** вручну один раз у редакторі Apps
   Script — Google попросить авторизувати доступ (Drive read-only + зовнішні
   запити), а сам скрипт поставить собі погодинний тригер. Перевірити в
   розділі **Triggers** (значок годинника зліва), що `scanAndPublish` там є.
6. Для ручної перевірки — запустити `scanAndPublish` і подивитись
   **Executions** (лог виконання).

Увесь конвеєр належить власнику Google-акаунта, який запускає скрипт —
GitHub PAT (і, якщо увімкнено, Anthropic-ключ) зберігаються лише в Script
Properties цього проєкту Apps Script, ніде більше.

## Чесні застереження
- **Картинки — найслабше місце.** У v1 автор вставляє в текст документа
  **посилання на вже розміщене фото** (або лишає без фото) — автоматичне
  вилучення вбудованих у Doc зображень не реалізоване. Якщо картинка потрібна
  в картці новини, розробник додає її вручну пізніше.
- **Без рецензії перед публікацією — лише коли шапку заповнено повністю.**
  Це свідомий вибір власника сайту для цього конвеєра. Якщо шапка неповна
  або дата/категорія не розпізнані — скрипт ставить `draft: true` замість
  вигадування, і новина не з'являється в стрічці, доки хтось не поправить
  `.md` вручну.
- **Повторне редагування документа.** Якщо автор редагує вже опублікований
  Doc, зміни на сайті автоматично НЕ підхоплюються (`docId` уже в
  `news-processed.json`) — правки в опубліковану новину вносяться вручну
  в `.md`-файл.
- **Формат шапки чутливий до стилю.** Поля розпізнаються лише як звичайний
  текст `Мітка: значення` на окремому рядку — без жирного, без нумерованого
  списку, без заголовка Google Docs. Якщо автор оформить шапку інакше,
  скрипт цього не розпізнає і піде в `draft: true` з дефолтами (не помилка,
  просто потребує ручної перевірки).
- **Квоти Apps Script.** Погодинний тригер + виклики Drive/GitHub API
  вкладаються у безкоштовні денні квоти Google для звичайного акаунта з
  великим запасом.

## Межа відповідальності
- **Автори новин** — Google Docs, тека `fcst_news`. Ніякого Git.
- **Розробники** — Claude Code з прямим доступом до репозиторію (код,
  шаблони, макети сторінок) — і далі через PR, окрім самого новинного
  конвеєра, який пушить напряму в `main`.
