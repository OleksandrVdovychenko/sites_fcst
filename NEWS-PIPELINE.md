# Заливка новин: Google Docs → сайт

Автори пишуть новини у Google Docs і не торкаються ні Git, ні CMS.
Автоматизація перетворює документ на новину й відкриває PR; публікує людина.

```
Google Doc  →  Apps Script  →  експорт у Markdown  →  Claude нормалізує у схему
            →  PR у GitHub  →  рев'ю (merge)  →  Cloudflare перебілд  →  на сайті
```

## Що робить автор
1. Пише новину у Google Doc (звичайний текст, підзаголовки, за потреби — фото).
2. Меню **«ФКНТ → Надіслати новину на сайт»** (або кладе документ у теку «На публікацію»).
3. Бачить повідомлення «надіслано на розгляд». Усе.

## Що робить система (`automation/publish-news.gs`)
1. Експортує Doc у Markdown (нативний експорт Google Docs).
2. Прогоняє через Claude API → чистий `.md` зі схемою (`title, date, category, summary, draft, body`).
3. Створює гілку, комітить `src/content/news/<slug>.md`, відкриває PR із посиланням на джерело.

## Разове налаштування
1. У Google Doc: **Extensions → Apps Script**, вставити `publish-news.gs`.
2. **Project Settings → Script properties**:
   - `GITHUB_TOKEN` — fine-grained PAT: лише репо `fcst-web`, права `contents:write` + `pull_requests:write`, **без** push у `main`.
   - `GITHUB_REPO` — напр. `fcst-kai/fcst-web`; `BASE_BRANCH` — `main`.
   - `ANTHROPIC_KEY` — ключ Claude API.
3. У `appsscript.json` додати scopes: `documents`, `drive.readonly`, `script.external_request`.
4. Захист гілки `main`: обов'язковий PR + рев'ю.
5. (Опційно) time-тригер, щоб сканувати теку замість кнопки в кожному документі.

## Чесні застереження
- **Картинки — найслабше місце.** Нативний експорт Docs не завжди зручно віддає вбудовані зображення.
  Для v1 радимо: автор вставляє **посилання на вже розміщене фото**, або фото додає розробник у PR.
  Витяг вбудованих зображень у `public/news/` — задача v2 (окрема гілка в скрипті).
- **Повторне надсилання.** Якщо автор редагує той самий Doc — щоб не плодити дублі,
  зберігайте `docId` у frontmatter і в скрипті шукайте наявний файл за ним (upsert). У цій версії — простий insert.
- **Секрети — лише у Script Properties / Cloudflare**, ніколи в репозиторії.
- **Рев'ю обов'язкове.** PR не зливається автоматично — це захист офіційного каналу.
- Скрипт написано ідіоматично, але його треба **протестувати на тестовому репо** перед бойовим.

## Альтернатива без ШІ
Якщо не хочете AI-крок: автор заповнює вгорі документа **таблицю-шапку**
(Заголовок / Дата / Категорія / Опис), а скрипт читає її через `DocumentApp`
і бере тіло після таблиці. Детермінованіше, але чутливе до форматування —
ШІ-варіант стійкіший до «живих» документів.

## Межа відповідальності
- **Автори новин** — Google Docs (цей конвеєр).
- **Розробники** — Claude Code з PAT напряму в репозиторій (код, шаблони, макети сторінок).
- Обидва потоки сходяться в PR і проходять рев'ю перед публікацією.
