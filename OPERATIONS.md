# Керівництво з експлуатації сайту ФКНТ

Один документ на все: як розробляти сайт далі, як додати новину, і як
керувати тим, хто має доступ до адмінки новин. Кожен розділ самодостатній
— можна одразу переходити до потрібного.

## Що це за сайт, коротко

Статичний сайт (Astro), деплоїться на Cloudflare Pages з `main`-гілки
GitHub-репозиторію `sites_fcst`. Новини — файли `.md` у
`src/content/news/`, і потрапляють туди трьома різними шляхами:

```
                    ┌─ людина/агент через Pull Request (розробка, разові правки)
Новина на сайті  ◄──┼─ Google Docs у теці "fcst_news"      (автори без Git)
                    └─ мікроадмінка /admin/                 (редактори без Git)
```

Перші два канали живуть довго (Docs-конвеєр, PR-процес), третій —
`/admin/` — новий, з'явився разом із цим документом.

## А. Розробка сайту далі

Повна версія правил — `AGENTS.md` (обов'язково до прочитання, якщо
вносиш зміни через AI-агента) і `README.md` (загальний огляд стеку). Тут —
стисло.

**Локальний запуск:**
```bash
npm install
npm run dev      # http://localhost:4321
npm run build    # перевірка перед PR — схема новин валідується тут
```

**Структура:**
- `src/layouts/Base.astro` — спільна шапка/меню/футер, одне місце на весь сайт.
- `src/components/` — перевикористовувані блоки (напр. `DepartmentCard.astro`).
- `src/data/*.json` — структуровані дані (кафедри, спеціальності тощо) — сторінки їх просто рендерять.
- `src/content/news/` — новини, по одному `.md` на статтю, схема — `src/content/config.ts`.
- `src/styles/tokens.css` — кольори/шрифти з брендбуку. Нових кольорів поза токенами не вводити.
- `functions/` — Cloudflare Pages Functions (бекенд мікроадмінки), деталі — `ADMIN-SETUP.md`.

**Золоте правило (для AI-агентів і людей однаково, крім двох задокументованих виключень):**
готуєш зміни → відкриваєш Pull Request → людина рев'ю й зливає. Ніхто не
пушить напряму в `main`, крім двох автоматизованих каналів публікації
новин (Docs-конвеєр і мікроадмінка) — вони комітять від імені
автентифікованої людини, не розробника.

**Довідка по інших документах:**
- `MIGRATION-PLAN.md` — які сторінки старого сайту ще не перенесені, і в якому порядку.
- `INFRASTRUCTURE.md` — де що зареєстровано (GitHub/Cloudflare/Google), для міграції на університетський акаунт.
- `NEWS-PIPELINE.md` / `ADMIN-SETUP.md` — детально про два автоматизовані канали новин нижче.

## Б. Як додати новину

Три способи — обери залежно від того, хто ти.

### 1. Я редактор, не хочу бачити код чи Git → мікроадмінка

1. Відкрити `https://sites-fcst.pages.dev/admin/` (згодом — `https://fcst.kai.edu.ua/admin/`, коли домен переключать).
2. Увійти корпоративним Google-акаунтом `@kai.edu.ua`.
3. **+ Нова новина** → заповнити заголовок, дату, категорію, короткий
   опис, текст (markdown — заголовки через `##`, списки, `**жирний**`,
   посилання `[текст](url)` тощо), за бажанням — обкладинку.
4. Щоб вставити картинку **всередину** тексту (не лише обкладинку) —
   курсор у потрібне місце → кнопка **🖼 Вставити зображення**.
5. **Опублікувати**. Сайт оновиться за секунди-хвилину (Cloudflare Pages
   перебілдовує автоматично).
6. Не готово публікувати одразу? Позначити **«Чернетка»** — новина
   збережеться, але не з'явиться в стрічці, поки чекбокс не зняти.

Немає рецензії перед публікацією — це свідомий вибір (див. `ADMIN-SETUP.md`
розділ «Чесні застереження»). Хто саме має доступ до `/admin/` — розділ В
нижче.

### 2. Я автор, просто пишу текст, навіть не знаю, що таке Git → Google Docs

1. Написати новину звичайним Google Doc-ом. **Перші рядки** — проста
   шапка, кожне поле на своєму рядку, без жирного/заголовків:
   ```
   Заголовок: Команда ФКНТ перемогла на хакатоні
   Дата: 2026-08-03
   Категорія: Досягнення
   Опис: Студенти посіли перше місце з проєктом виявлення кіберзагроз.
   Зображення: https://.../фото-для-обкладинки.jpg
   ```
2. Порожній рядок → далі звичайний текст новини. Картинка всередині тексту
   — просто посилання на фото окремим рядком у потрібному місці.
3. Покласти документ у теку **fcst_news** на Google Диску.
4. Протягом години погодинний скрипт сам підхопить документ і опублікує.
   Якщо шапку заповнено не повністю — новина все одно з'явиться в
   репозиторії, але з `draft: true`, і не покажеться на сайті, доки хтось
   не перевірить `.md`-файл вручну.

Докладно, включно з технічною стороною — `NEWS-PIPELINE.md`.

### 3. Я розробник/агент, працюю через Git → Pull Request

1. Файл `src/content/news/РРРР-ММ-короткий-слаг.md`, frontmatter за
   схемою `src/content/config.ts` (`title`, `date`, `category`, `cover?`,
   `summary`, `draft`).
2. `npm run build` — має пройти без помилок.
3. Відкрити PR, описати, звідки факти, дати рецензенту зливати.

Докладно — `AGENTS.md`.

## В. Хто має доступ до адмінки новин, і як це змінити

**Модель доступу — один список, одне місце для змін.**
Cloudflare Access (вхід через Google) — просто вимагає, щоб людина
залогінилась через Google, і **не** обмежує, хто саме. Реальний фільтр —
змінна середовища `ALLOWED_EMAILS` у Cloudflare Pages.

### Додати редактора
1. Cloudflare Pages dashboard → проєкт `sites-fcst` → **Settings →
   Environment variables (Production)**.
2. Відкрити `ALLOWED_EMAILS`, дописати новий email через кому:
   `oleksandr.vdovychenko@kai.edu.ua, novyi.redaktor@kai.edu.ua`.
3. Зберегти → **Retry deployment**, щоб Functions підхопили нове значення.
4. Готово — нічого в Cloudflare Access (Zero Trust) чіпати не потрібно.

### Прибрати редактора
Те саме, але видалити його email зі списку — так само зберегти й
Retry deployment. Доступ зникає одразу після редеплою.

### Чому нема сенсу керувати цим через Cloudflare Access policy
Так було спочатку (список email у Cloudflare Access **і** в
`ALLOWED_EMAILS` одночасно) — довелось міняти в двох місцях і стежити,
щоб не розійшлись. Тепер Access policy — навмисно generic («хто завгодно
з Google-акаунтом»), а `/admin/*` і `/api/*` захищені в коді
(`functions/_lib/access.ts`) на основі `ALLOWED_EMAILS`. **Важливо:** якщо
`ALLOWED_EMAILS` порожня або не існує як змінна — код трактує це як «без
обмежень», і пускає будь-кого, хто пройшов Google-логін. Завжди перевіряй,
що змінна реально існує в Cloudflare Pages, а не лише що в ній правильне
значення.

Детально про саме налаштування (Cloudflare Access Application, Google
OAuth) — `ADMIN-SETUP.md`.

## Відомі відкриті питання

- Кастомний домен `fcst.kai.edu.ua` ще не переключений на новий сайт (усе
  ще на pages.dev-адресі) — `INFRASTRUCTURE.md`, розділ 6.
- Пункти меню (напр. «Викладачу») не можна реально приховати від
  неавторизованих відвідувачів без переведення відповідних сторінок на
  серверний рендеринг (SSR через Cloudflare Pages Functions) — зараз сайт
  повністю статичний, однаковий HTML для всіх. Обговорено, поки не
  заплановано — коли актуалізується, це окрема архітектурна задача, не
  косметична правка меню.
- Уся інфраструктура — на особистих акаунтах власника, міграція на
  університетські — `INFRASTRUCTURE.md`.
